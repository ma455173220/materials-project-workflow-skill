# Example personal default: 2D adsorption route

This is one researcher's saved route, kept as an example of what a personal default may contain. Apply it only when the researcher's own default or the current project selects it. A project may omit, replace or reorder stages. These are suggestions for **2D adsorption** work, not universal rules or settings for 3D cells.

1. Inspect existing local and HPC results before computing. For a chosen adsorption problem, use the ML tool named in the saved default (or the project's chosen tool) and directly relax all site/rotation starts to the Skill's default ML force criterion and step limit (unless the project chooses others) in one screening stage; do not split this default into coarse and fine ML passes. Select three low-energy representatives by **final geometry and site diversity**; a distinct same-site orientation may deserve a place. Explain the selection in `selected/`, a real directory (not a link) in the local project. The candidate count is a project choice for other routes.
2. Send the selected candidates to DFT coarse 1 after the first actual HPC input review. For this 2D route, use `LREAL=Auto`, Gamma `1×1×1` and `vasp_gam` regardless of in-plane length. Check each candidate's electronic/ionic convergence and common settings before ranking. Present the structures and recommendation in `STATUS.md`; **the researcher chooses** the candidate that advances.
3. If both in-plane lattice lengths `a,b > 15 Å`, proceed to fine geometry optimization with Gamma `1×1×1` and `LREAL=.FALSE.`. Otherwise, use coarse 2 with `LREAL=Auto`, a VASPKIT 102 Monkhorst–Pack mesh generated using reciprocal-resolution input `0.04` (in `2π×Å⁻¹` units), and `vasp_std`; fine optimization keeps that mesh and uses `LREAL=.FALSE.`. This 15 Å rule is a route heuristic, not a k-point convergence proof. The c-direction one-point rule is **only for 2D** systems.
4. A separately chosen denser-k single-point is a different objective. If its forces fail the project's geometry criterion and the work budget allows, reoptimize at that target mesh in two steps (`LREAL=Auto`, then `.FALSE.`), then evaluate comparable final energies under common settings.

This route chooses verified VTST FIRE for DFT geometry optimization, coarse and fine, switching to native CG only when the optimizer itself fails; see [optimizer and recovery guidance](vasp-recovery.md). Use the stage's chosen force criterion and judge actual convergence. Diagnose before changing an ongoing attempt. Do not carry a coarse or rescue energy into final comparisons without the common formal energy protocol; matching energy-affecting settings does not require matching optimizer tags.

For CPU pure-MPI jobs, record a per-site `NCORE` starting value in the default after checking the actual rank/thread/GPU layout and site script; do not silently replace it with `NCORE=1` or copy it to another site (a run that writes Wannier data is the exception; see [Wannier guidance](wannier.md)). Set `ENCUT` explicitly to at least `1.3 × max(ENMAX)` from the actual ordered POTCAR used by that run. For a family of calculations whose energies will be compared, choose one common `ENCUT` satisfying this lower bound for every member. A primitive cell may use `EDIFF=1E-7`; for a supercell choose `EDIFF` in the `1E-6` to `1E-5` range according to size, SCF behavior and required accuracy, keeping the selected final setting consistent across comparable runs. One historical slab relaxation used `ENCUT=520` and `EDIFF=1E-5`, along with `EDIFFG=-0.02`, `NELM=100`, `NELMIN=4`, `NSW=1000`, `ISIF=2`, `ISMEAR=0`, and `SIGMA=0.05`; these historical values are examples, not substitutes for the current POTCAR/cell checks or the current optimizer choice. Select spin, dispersion, dipole correction, smearing and final precision for the actual system and show the first real INCAR for review. Keep one stable keyword order across related inputs. After a fully finished and accepted final relaxation, extract the last ionic-step `F` and `E0` from `OSZICAR`, comparing only one project-consistent energy definition; no separate static job is automatic.

For adsorption inputs, use these additional starting rules; retain the project's reviewed method across comparable runs:

- Set `LWAVE=.FALSE.` and `LCHARG=.FALSE.` when WAVECAR/CHGCAR are unnecessary; enable either deliberately when a restart or analysis needs it. `LCHARG` is the VASP tag, not `LCHGCAR`. Keep `LORBIT=11` by default for projected output, accounting for its PROCAR output.
- Include an appropriate `IVDW` dispersion method for molecular adsorption. `IVDW=12` is D3(BJ); confirm that it matches the project's functional and use the same dispersion protocol for the compared slab, adsorbate and references. Do not add a second dispersion treatment to a functional that already includes one.
- Choose `ISPIN=2` and `ISYM=0` when the actual structure and magnetic/symmetry question warrant them. For `ISPIN=2`, select `MAGMOM` from plausible local moments and magnetic order; all-zero values may be one nonmagnetic starting test, but do not assume they explore a magnetic state. To test a distinct magnetic initialization, use an appropriate fresh electronic start or nonmagnetic density rather than merely changing `MAGMOM` while reusing a spin-polarized WAVECAR/CHGCAR; check the actual initial and converged moments.
- If using `IDIPOL` for energy correction, with or without `LDIPOL` for potential/force correction, calculate `DIPOL` for the current slab/adsorbate structure rather than copying an older geometry's value. Use a verified center-of-mass script or calculate the mass-weighted center directly, accounting for periodic wrapping if the structure crosses a cell boundary; express `DIPOL` in fractional (Direct) lattice coordinates and record the source geometry. `LDIPOL` also requires the appropriate `IDIPOL`.

Tag references: [VASP restart/output switches](https://vasp.at/wiki/Restart_and_output_files_cheat_sheet), [MAGMOM](https://vasp.at/wiki/MAGMOM), [DIPOL](https://vasp.at/wiki/DIPOL), [IVDW](https://vasp.at/wiki/IVDW).

For reaction paths this route uses **CI-NEB, never conventional non-climbing NEB**, with IDM to rescue a difficult CI-NEB; read [transition-state guidance](transition-states.md). The first representative CI-NEB and first representative IDM each get input review before submission and result review after completion. The site CI-NEB script runs one node per moving image, so its node count equals INCAR `IMAGES`. Standalone frequency validation is only for paths the researcher names. Frequency starting settings are `IBRION=5`, `POTIM=0.015`, `NFREE=2` and `NWRITE=3`, with all slab atoms fixed and the adsorbed molecule free; IDM direction-finding may include reacting surface atoms when the mechanism requires them.

POTCAR is often generated on HPC with VASPKIT task 103, but verify the project's actual species/potential rule during the first input review. Start the site script from the researcher's successful example when available. Apart from what the saved default sets, ML model, HPC account, site paths, available hours, access method and scientific thresholds belong to the current project, not this template.
